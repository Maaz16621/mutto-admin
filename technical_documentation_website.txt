# Technical Documentation: Mutto Car Wash Platform

## 1. Project Overview

The Mutto Car Wash Platform is a comprehensive system designed to manage car wash services, including an administrative panel for staff and backend services for booking, payments, and notifications. The project is structured into three main components: a React-based frontend admin panel, a Node.js Express API backend, and Firebase Cloud Functions for serverless operations.

## 2. Architecture

The application follows a distributed architecture comprising three main logical units:

### 2.1. Frontend: React Admin Panel

*   **Technology:** React.js, Chakra UI, Leaflet
*   **Purpose:** Provides a user interface for administrative tasks, including managing users, services, bookings, and other business-critical data. It features interactive maps for location-based functionalities.
*   **Key Files:** `src/index.js` (entry point), `src/layouts/`, `src/views/`.
*   **Deployment:** Hosted via Firebase Hosting and Genezio.

### 2.2. Backend API: Node.js Express Application

*   **Technology:** Node.js, Express.js, Firebase Admin SDK, Axios, body-parser, cors.
*   **Purpose:** Serves as a RESTful API layer, handling business logic, data interactions, and integrations with external services. It exposes endpoints for user management, place details, service retrieval, and database operations.
*   **Key Files:** `api/index.js` (entry point), `api/deleteUser.js`, `api/placeDetails.js`, `api/getServices.js`, `api/updateVehicleType.js`, `api/bookingCompleted.js`, `api/copyDb.js`.
*   **Deployment:** Deployed as a Node.js application (potentially on Cloud Run or similar services, given the `PORT` configuration).

### 2.3. Serverless Functions: Firebase Cloud Functions

*   **Technology:** Firebase Functions, Firebase Admin SDK, Stripe, Day.js.
*   **Purpose:** Handles specific event-driven backend tasks and integrations, particularly for payment processing, time slot management, and various notification mechanisms. These functions execute in response to Firebase triggers or HTTP requests.
*   **Key Files:** `functions/index.js` (entry point), `functions/src/createPaymentIntent.js`, `functions/src/getAvailableTimeSlotsV2.js`, `functions/src/handleBookingNotification.js`, etc.
*   **Deployment:** Deployed as Firebase Cloud Functions.

## 3. Technologies Used

*   **Frontend:**
    *   **React.js:** JavaScript library for building user interfaces.
    *   **Chakra UI:** A simple, modular, and accessible component library for React.
    *   **Leaflet:** An open-source JavaScript library for mobile-friendly interactive maps. `leaflet-draw` is used for drawing tools on maps.
    *   **react-router-dom:** Declarative routing for React.
*   **Backend API:**
    *   **Node.js & Express.js:** JavaScript runtime and web application framework for building the RESTful API.
    *   **Firebase Admin SDK:** Used for interacting with Firebase services (Firestore, Authentication, etc.) from the backend.
    *   **Axios:** Promise-based HTTP client for the browser and Node.js.
    *   **body-parser, cors:** Middleware for handling request bodies and Cross-Origin Resource Sharing.
*   **Serverless Functions:**
    *   **Firebase Functions:** Google's serverless framework for automatically running backend code in response to events.
    *   **Stripe:** Payment processing platform integration for handling transactions.
    *   **Day.js:** A minimalist JavaScript library for parsing, validating, manipulating, and formatting dates.
    *   **firebase-admin:** Used to access Firebase services in the serverless environment.
*   **Development Tools:**
    *   `npm` for package management.
    *   `gulp` for task automation (e.g., licenses).
    *   `eslint`, `prettier` for code quality and formatting.

## 4. Key Components & Functionality

### 4.1. Frontend (Admin Panel)

*   **User Interface:** Built with React and Chakra UI, offering a responsive and accessible admin experience.
*   **Routing:** Manages navigation between different sections of the admin panel (authentication, dashboard, etc.).
*   **Map Integration:** Utilizes Leaflet for displaying and interacting with geographical data, likely for service areas or worker locations.
*   **Data Visualization:** Likely uses libraries like `react-apexcharts` and `react-chartjs-2` for displaying analytics and data trends.

### 4.2. Backend API

*   **User Management:** Endpoints for operations related to user data (e.g., `deleteUser`).
*   **Location Services:** Integration with external location APIs (`placeDetails`, `nominatimProxy`, `googleToOsm`) for geographical data and address lookups.
*   **Service Retrieval:** Provides access to available car wash services (`getServices`).
*   **Database Operations:** Contains logic for interacting with the database, including copying data (`copyDb`).
*   **Booking Completion:** Handles logic related to finalizing bookings (`bookingCompleted`).
*   **Vehicle Type Updates:** Provides an endpoint to trigger updates for vehicle types (`updateVehicleType`).

### 4.3. Firebase Cloud Functions

*   **Stripe Integration:**
    *   `createStripeCustomer`: Creates a new customer in Stripe.
    *   `createSetupIntent`: Sets up payment methods for future use.
    *   `createPaymentIntent`: Processes payments for bookings.
*   **Time Slot Management:**
    *   `getAvailableTimeSlotsV2`, `getAvailableTimeSlotsV3`: Retrieves available booking slots based on various criteria.
    *   `reserveTimeSlot`: Marks a time slot as reserved.
    *   `releaseTimeSlot`: Releases a previously reserved time slot.
*   **Notifications:**
    *   `handleBookingNotification`: Manages notifications related to booking events.
    *   `sendPushOnNewNotification`: Sends push notifications.
    *   `sendChatNotification`: Handles chat-related notifications.
*   **Scheduling:**
    *   `scheduleBookingReminder`: Schedules reminders for upcoming bookings.

## 5. Deployment

The project utilizes both Firebase and Genezio for deployment:

*   **Firebase Hosting:** The frontend React application (`build` directory) is hosted on Firebase Hosting, serving as a single-page application.
*   **Firebase Functions:** The serverless functions are deployed to Firebase Functions, executing on demand.
*   **Genezio:** An additional deployment configuration for the frontend is present (`genezio.yaml`), suggesting an alternative or complementary deployment strategy for the React application.
*   **Cloud Run (Inferred):** The Node.js Express API is likely deployed on a containerized platform like Google Cloud Run, given the `PORT` configuration in `api/index.js`.
